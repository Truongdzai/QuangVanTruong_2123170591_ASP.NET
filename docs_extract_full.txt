[664|Heading 2] 🏗️ PHẦN 1: CÀI ĐẶT THƯ VIỆN (NUGET PACKAGES)
[665|normal] cần cài đặt 3 "vũ khí" quan trọng vào Project CMS.Data:
[666|normal] Microsoft.EntityFrameworkCore.SqlServer: Để làm việc với SQL Server.

[913|normal]                 .Where(p => p.CategoryId == id)
[914|normal]                 .OrderByDescending(p => p.CreatedDate)

[923|Heading 3] B. Giải thích chi tiết
[924|normal] Tham số int? id: Dấu chấm hỏi ? cho phép id có thể bị rỗng (null) nếu người dùng không gõ số ID trên URL. Điều này giúp chương trình không bị lỗi "văng" ngay lập tức.
[925|normal] .Where(p => p.CategoryId == id): Đây là biểu thức Lambda. Hệ thống sẽ quét bảng Posts và chỉ chọn những dòng nào có cột CategoryId khớp chính xác với con số mà  truyền vào từ trình duyệt.
[926|normal] .OrderByDescending: Giúp bài viết vừa đăng xong sẽ hiện lên vị trí đầu tiên, giống như các trang báo điện tử hiện nay.
[927|normal] Tổng quát: công thức "vàng" này để áp dụng cho mọi bảng dữ liệu:
[928|normal] Biến_Kết_Quả = _context.Tên_Bảng
.Hàm_Lọc
.Hàm_Sắp_Xếp
.Hàm_Liên_Kết.Thực_Thi();
[929|Heading 3] Giải thích chi tiết các "Mắt xích"
[930|normal] _context.Posts: Điểm bắt đầu. Nó đại diện cho bảng dữ liệu trong SQL Server mà đã cấu hình ở Buổi 2.
[931|normal] .Where(p => ...): Màng lọc dữ liệu.
[932|normal] p đại diện cho một dòng trong bảng (Post).
[933|normal] p.CategoryId == id là điều kiện lọc: "Chỉ lấy những bài viết có mã danh mục bằng với tham số truyền vào".
[934|normal] .OrderByDescending(p => ...): Bộ sắp xếp.
[935|normal] Dùng để đưa dữ liệu mới nhất (ngày lớn nhất) lên đầu trang.
[936|normal] .Include(p => p.Category): Lệnh nạp chồng (Join bảng).

[2274|Heading 2] 1. KHÁI NIỆM TRỌNG TÂM: API LÀ GÌ?
[2275|normal] Trong các buổi trước, chúng ta dùng MVC (Model-View-Controller) để trả về các trang web (HTML). Tuy nhiên, để làm việc với các ứng dụng hiện đại như ReactJS, Mobile App, Backend không trả về giao diện mà chỉ trả về Dữ liệu thô (JSON).

[2278|Heading 3] 1. Sự khác biệt giữa Web truyền thống (MVC) và Web hiện đại (API + Frontend)
[2279|Heading 4] Cách làm cũ (ASP.NET Core MVC):
[2280|normal] Cơ chế: Khi người dùng yêu cầu một trang web, Server sẽ thực hiện: Lấy dữ liệu -> Gắn dữ liệu vào file HTML (View) -> Trả về nguyên một trang web hoàn chỉnh.
[2281|normal] Nhược điểm: Server vừa phải lo dữ liệu, vừa phải lo giao diện. Nếu muốn làm thêm ứng dụng Mobile, bạn phải viết lại toàn bộ từ đầu vì Mobile không đọc được file HTML của Web.
[2282|Heading 4] Cách làm hiện đại (Web API):
[2283|normal] Cơ chế: Server chỉ tập trung làm đúng một việc: Cung cấp dữ liệu thô.
[2284|normal] Giao diện: ReactJS (Web), Flutter (Mobile) hay Swift (iOS) sẽ tự xây dựng giao diện riêng của mình. Khi cần dữ liệu, chúng "gõ cửa" Server để lấy.
[2285|normal] Ưu điểm: Một Backend (API) có thể phục vụ cùng lúc cho nhiều nền tảng (Web, App, IoT...).
